# 商品列表字段映射与展示设计

## 背景

用户提供的“最终导出字段.xlsx”包含 37 列商品字段。当前 `index.html` 的 Chatflow 商品 JSON 解析、Markdown 表格和右侧商品列表使用了旧字段映射，英文键兼容不完整，也缺少若干中文字段名；商品链接、店铺链接和主图链接没有全部作为独立列展示。因此后端已经返回字段时，部分数据会显示为 `--` 或无法在列表中核对。

## 目标

- 页面商品列表严格按照 Excel 的 37 列及顺序展示。
- 后端返回字段按照中文列名和现有英文键名建立兼容映射。
- 商品链接、店铺链接、主图链接分别作为独立字段展示，并保持可点击。
- 返回数据缺失时显示 `--`，不生成或推断数据。
- 保持现有商品 JSON 提取、会话恢复、排序、预览和导出行为。

## 非目标

- 不修改后端接口、鉴权、请求参数或 SSE 协议。
- 不新增 Excel 字段之外的展示列。
- 不重构整体布局或拆分单文件页面。

## 方案

在现有 `productJsonToMd()` 字段投影处集中补充别名映射。每列先读取后端可能使用的中文列名，再兼容已支持的英文旧键；数值和比例字段保留后端原始格式，不额外换算。所在地优先读取“所在地”，否则由省、市字段组合。公司类型支持已有枚举值与中文文本。主图链接与商品主图分别读取：主图用于缩略图展示，主图链接展示完整可点击 URL。

同一份字段投影继续服务聊天内商品表格、右侧商品列表及现有预览/导出路径，避免两套字段映射产生差异。若右侧商品列表的字段模型无法表达某列，则只增加最小适配，不改变既有筛选和排序语义。

## 数据流

1. SSE 或历史会话文本通过现有 `extractProductJson()` 提取 `data.products`。
2. 字段映射层按 Excel 列顺序从中英文别名中读取值。
3. 缺值统一输出 `--`；链接字段作为有效 URL 转为可点击链接。
4. 生成的 37 列结果供聊天表格和既有右侧商品数据预览/导出链路使用。

## 验证

- 以用户上传的 Excel 表头核对列数、名称和顺序，确保精确为 37 列。
- 使用真实后端商品响应逐列比对：有值的字段显示正确，缺字段显示 `--`。
- 验证商品详情、店铺和主图链接分别可点击且目标 URL 对应正确。
- 验证商品 JSON 流式完成和历史会话恢复均展示同样字段。
- 验证右侧列表、排序、预览和导出没有回归。
- 在浏览器中检查宽表横向滚动和文本溢出，不遮挡其他控件。

## 风险与边界

后端字段命名可能继续变化。字段映射应集中维护并使用明确别名，避免在多个渲染函数内重复判断。若某项 Excel 列对应字段没有出现在当前真实响应中，应如实显示 `--`，并记录为后端数据缺口，不从其他指标推导。
