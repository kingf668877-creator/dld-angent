# 流式分析过程防闪烁设计

## 背景
线上页面调用接口已经能够正常返回数据，但流式分析阶段存在视觉闪烁。当前 `index.html` 在高频 SSE 事件到达时反复写入分析正文、阶段样式并触发滚动，同时分析图标和骨架元素带有持续动画。

## 目标
- 保持分析阶段实时可见。
- 降低高频流式事件造成的 DOM 重排和滚动抖动。
- 阶段状态只向前推进，不来回跳转。
- 保持最终表格、错误处理、停止生成和会话逻辑不变。

## 非目标
- 不修改接口地址、请求参数或 SSE 协议。
- 不改变最终答案和表格解析逻辑。
- 不重构整页布局或拆分单页文件。

## 方案
### 渲染节流
在流式分析状态中增加待刷新文本和刷新定时器。`updateAnalyze()` 只更新缓存，并以约 120ms 的节奏批量写入 `.analyze-body`。刷新前比较文本，内容未变化时跳过写入；刷新后仅在分析区域仍存在时滚动其内部容器。

### 滚动节流
对对话区域的自动跟随增加短周期节流，并沿用已有的“用户接近底部才跟随”规则。分析正文更新不再直接触发整页滚动，避免每个 token 都引发页面定位变化。

### 阶段单向推进
`applyStage()` 增加单向保护：自动推断得到的阶段小于当前阶段时忽略；节点事件指定的阶段也不允许把状态回退。阶段文本和步骤 class 只有发生真实变化时才写入。

### 动画与布局稳定
移除分析图标的无限 `azPulse`，保留一次性卡片入场动画。分析正文设置稳定的最小高度和固定的滚动边界，步骤条不因内容更新改变布局。表格骨架屏保留现有进度条，但避免重复设置相同文本和宽度。

### 生命周期清理
在成功、失败、停止和切换会话时清除分析刷新定时器及待刷新任务，防止旧请求继续修改已移除的 DOM。

## 数据流
1. SSE 事件进入 `appendDelta()` 或 `onEvent()`。
2. 分析文本写入缓存，阶段计算只产生单向状态候选值。
3. 定时刷新器批量更新分析正文和必要的阶段样式。
4. 用户仍在底部时执行节流后的跟随滚动。
5. `onDone()`、错误或停止时统一刷新并清理定时器。

## 验证标准
- 连续流式输出期间，分析卡片不反复淡入、不上下跳动。
- 分析阶段顺序不会从后一步退回前一步。
- 用户上滑查看历史内容时，不会被自动滚回底部。
- 完成后最终商品表格与现有线上测试结果一致。
- 失败和停止后不再有后台定时器更新页面。
- Chrome 控制台不出现旧 DOM、定时器或未捕获异常。

## 风险与回滚
主要风险是节流时间过长导致进度反馈延迟，因此将刷新间隔控制在约 120ms，并在完成或错误时立即刷新一次。若验证发现滚动体验变差，可只回滚滚动节流，保留文本节流、阶段单向推进和动画调整。
